# Narwhal 3D project status

Narwhal 3D is an extremely early public prerelease. This page records what currently works and what remains incomplete so visible UI does not imply unsupported behavior. Package versions remain on the `0.4.x` line until the project owner explicitly lifts that cap.

## Current source and 0.4.13 feature set

The Linux AppImage and Windows portable EXE for [0.4.13](https://github.com/ContributionRich/Narwhal3D/releases/tag/v0.4.13) are published, both built from tagged source 95b8decd45384307849add7c47ea6e57372367d4. This release adds the Library tab, Rust-coordinated background native-project I/O, crash recovery, command and unit fixes, and further Rust computational ownership. Both packages retain the exact-save helper, qualified document observer and TracePicture helper.

Linux acceptance covers extracted-package integrity, exact torus/project round trips, TracePicture, Library, native calculations and real packaged GUI shell interaction. Windows acceptance ran in a Windows 11 VM: 557 Rust tests, four error-format checks, eleven extracted-package suites and ten actual portable-EXE checks. Windows math fixtures preserve independently captured platform-specific exact answers. The EXE is unsigned and GUI acceptance used software OpenGL, not a physical GPU. ELF symbol ceilings do not certify every Linux distribution; the older glibc 2.28 build environment differs on two captured math-bit assertions and is not runtime-qualified by the newer-host test run.

macOS is not targeted for this release; the historical Apple Silicon 0.4.8 package is unchanged. Consult the release notes for checksums and detailed validation limitations.

- **Current source AI (not the published 0.4.13 binaries):** Rust validates bounded typed modeling batches, dependencies, Review/Build authority, inspection and stable-object edits; the existing exact geometry kernel remains authoritative. Review requires approval; Build is a persistent local opt-in, not permission for arbitrary commands. Exact primitives, curves, extrusion, booleans, loft, open-rail pipe and revolve have focused host coverage, including Undo/Redo and project reload. General layer/group control and unrestricted command execution are not implemented.
- Viewport sharing requires separate one-shot local consent. Export is STEP or selected-object 3dm, requires a new local destination on every call, refuses overwrites, and never accepts a provider path. AI diagnostics in Bug Report are separately opt-in and contain structural metadata, not chat/images/credentials.
- Modeling display preparation uses bounded disposable workers before publication. Prepared display data is bound to the exact prelaunch master serialization (SHA-256, without triangulation), rechecked on collection and every use; identity alone is insufficient for mutable SDK handles. Failure/cancellation refuses publication, never replacing analytic geometry or retrying meshing synchronously. Display meshing can be canceled while running; construction cancellation is checked between SDK steps. Final publication remains synchronous (about 2.5 seconds in a recorded case, not a maximum-time guarantee).
- **Platform qualification is component-specific:** a separate Windows VM run passed the supervisor executable's 5 unit tests plus 1 worker-policy test and the automation **library's 125 unit tests**. Supervisor process-tree EOF/byte cancellation, no-opt-in behavior, timeout and a 96MiB memory guard were exercised. This is not all 149 Linux automation tests, Windows modeling/OCP display-job qualification, or a new release. The external automation/MCP **server is currently Unix-only**; its Windows build fails on Unix socket/FD/signal APIs already present in the source baseline. The Windows in-app library is a distinct component. macOS display-worker containment is unqualified and this display route explicitly refuses there.
- **Design quality remains limited:** measured exact clock features and follow-up edits do not establish robust whale/taco aesthetics. Reviewed real-provider outputs remain crude assemblies; successful tool completion is not visual acceptance. Broader resumability, general layer/group controls and separately approved MCP screenshot sharing remain incomplete. Real-provider tests are explicit opt-ins, never default network-dependent gates.
- The revised welcome window shows installed version and actual update status. The AI panel uses role-aware messages, truthful request status and centered action labels; Bug Report uses a category dropdown and one full-width Submit report action.
- The read-only MCP entrypoint supports both protocol eras (2025-11-25 and 2026-07-28) and nine bounded metadata tools. Build/stage matching native automation components for source use; old 0.4.7 binaries do not gain these features automatically. The Windows package includes the in-app automation library, not the Unix-only external MCP transport.
- **Source-only with the optional exact-Brep writer:** bounded multi-section Freeform `Sweep1` accepts 2–4 compatible open rational quadratic sections entered by name or by individually ordered whole-curve picks, with direction-alignment markers. It uses physical station mapping, exact NURBS document representation, source-identity checks and one undoable result. Fitting remains tolerance-qualified; this is not arbitrary-profile or private-algorithm parity. Unordered batch picks, multi-section components and multi-section Roadlike refuse explicitly. The existing single-section component route is retained; hybrid typed/mouse construction consumes the validated UUID geometry even after a rename. The Linux and Windows packages (0.4.10 onward) include the exact writer; the macOS package does not yet, and there the bounded multi-section publication route refuses rather than using an approximate document face.
- New surface publication and failure paths preserve existing documents/displays/history; exact project round trips and imported STEP geometry are tested. This is source validation, not a newly certified release package.
- A source check is not package certification: published assets require the frozen-source and extracted-package gates documented in `packaging/RELEASING.md`. CageEdit remains an explicitly limited mode, not full deformation parity. The Mac document worker has final-image memory containment and forbids fork/exec before parsing. The separate Corel multiversion helper remains unavailable on Mac.

## Command compatibility

Narwhal 3D is **not yet at full command parity with established NURBS CAD workflows**. It has a substantial working command set, but many commands, advanced options, selection routes, dialogs, and viewport tools remain missing or incomplete. A registered command name means that command is runnable; it does not guarantee every advanced option or interaction path is complete.

The authored menu hierarchy exposes all 190 commands currently registered by Narwhal, plus Recent Files and 363 individually named unavailable commands with `(Not implemented)` labels. File includes recent/recovery, template, and document groups; Help includes learning/reference and support groups. The desktop toolbar workspace contains 582 top-strip slots across fifteen tabs plus the 37-cell left tool palette and its 28 linked flyouts. Of the 525 non-separator top slots, 122 currently invoke registered commands; every unavailable action remains visible, identifies itself on hover, and explains the gap when clicked.

The issue tracker is the live source for bounded contribution work. Fully specified tasks carry the [`agent-ready`](https://github.com/ContributionRich/Narwhal3D/issues?q=is%3Aissue+is%3Aopen+label%3Aagent-ready) label.

Axis-based `Helix`, variable-radius `Spiral`, exact `Conic`, `Parabola`, `Hyperbola`, polyline/point-to-curve conversion, compatible `TweenCurves`, tolerance-qualified `Catenary`, C1 `HandleCurve`, and surface-control-polygon extraction now create real curve geometry with live previews where point-driven; planar `Flat` Spiral is supported. Sweep1 and Sweep2 rail prompts accept exact Ctrl+Shift-selected surface/solid edges as well as standalone curve objects. `AroundCurve` remains explicitly unavailable until its moving-frame convention is measured.

Major missing or incomplete areas include advanced curve and surface construction, deformation tools, some solid-editing operations, advanced viewport arrangements, document/options panels, rendering features, and many less-common command options. Examples that are not currently implemented include `Bend`, `Twist`, `Taper`, `Flow`, `BlendSrf`, `FilletSrf`, `NetworkSrf`, `Patch`, `MatchSrf`, `Untrim`, and `BooleanSplit`.

This status stays intentionally high-level. The public issue tracker contains detailed, bounded work that contributors can act on.

Unsupported behavior must be reported explicitly. Narwhal should never silently run a different command or substitute faceted manufacturing geometry.

## Viewport display modes

The following modes are implemented:

- **Wireframe**
- **Shaded**
- **Rendered**

They can be selected from:

- the **Display** tab in the right dock;
- the viewport-title menu opened from a viewport title;
- the `SetDisplayMode` command, with Active or All viewport scope;
- `Ctrl+Alt+W`, `Ctrl+Alt+S`, and `Ctrl+Alt+R`.

`Ghosted` and `X-Ray` are recognized but not implemented yet. Rendered mode currently uses the bundled viewport renderer and Narwhal's soft ground-shadow pass; it is not a complete photorealistic rendering pipeline.

## Geometry and interchange limitations

- Viewport tessellation is display-only and must not become document or manufacturing geometry.
- Exact solid operations use Open CASCADE and must preserve analytic surfaces and airtightness.
- Box and extrusion faces, edges, and vertices can be moved through the Rust/OCCT local-edit core, including curved extrusion walls and vertices moved out of six-edge caps. Such a cap, including one already reshaped by earlier edits, becomes one smooth exact bicubic NURBS height field over its original plane: Rust fits it, and OCCT builds a face whose edge tolerances are measured to bound the true gap, at most 1e-6 of the part size times four. Exact composite NURBS with a topology-aware fast path and exhaustive fallback remain the fallback. This also covers repeated edits after incident faces become exact NURBS, and further edits after a selective analytic fillet. A boundary-exact direct edit may introduce a measured NURBS crease when all topology, mapping, validity, self-intersection, and airtightness certificates pass. Standalone one-face Sweep1 surfaces support point, boundary-curve, and whole-surface movement while remaining valid exact open BReps. Every part of every catalogued solid moves in any direction: boxes, pyramids, extrusions of any profile, booleans, faces with holes, fillets, cylinders, cones, tubes, spheres and tori. Walls that close through a seam become exact ruled surfaces between their rims, and cone tips and sphere poles stretch the surface smoothly. A test with 1,944 moves enforces this. The one known refusal is a sideways pole stretch of a B-spline ellipsoid, which OCCT's self-intersection check cannot certify. Open surfaces and polysurfaces move the same way: planar surfaces with or without holes, lofts, edge surfaces, Sweep1, Sweep2, open pipes, open extrusions, open cones and partial revolves. Each edit is sewn back and must keep its boundary, and a curved wall between two rims keeps its curvature when one rim moves. Revolve produces an exact OCCT shape with a replayable recipe.
- Solid-part Gumball motion keeps the shaded source and draws a complete prospective boundary wireframe for face/edge/vertex edits; only real analytic BRep boundaries are displayed after commit, and release performs one fully validated exact native solve. Free Perspective movement tracks on a camera-facing plane and Grid Snap rounds all three local CPlane coordinates in Rust instead of flattening depth. Non-uniform scaling of an edited NURBS solid retains exact transformed NURBS and avoids OCCT's unsafe optional face-recognition healer.
- `.narwhal` is the built-in active project format. Its Rust-validated v1 container stores document metadata plus checksum-protected exact OCCT BReps for every analytic master; Save/Open does not depend on the optional openNURBS writer.
- STEP remains the recommended exact solid interchange format for other CAD/CAM systems.
- Public source includes Narwhal's bounded ONBREP helper and an exact-revision developer build recipe. The helper closes only sub-tolerance UV trim round-off and refuses larger gaps, preserving exact 3-D curves and surfaces. The Linux and Windows packages bundle the linked openNURBS helper (owner decision on redistribution, 2026-11-02; license text in `licenses/openNURBS-LICENSE.txt`). The macOS package does not yet, so there some Open CASCADE multi-face solids cannot be stored as exact `.3dm` Breps; the application warns rather than claiming a faceted save is exact.
- PDF and Adobe Illustrator import can use an optional converter pack that is not bundled in the 0.4.7 AppImage or Windows portable ZIP.
- CorelDRAW `.cdr` v15 Import/Open and Export/Print use Narwhal's built-in checked codec. On Linux and Windows, version16,17,and18 Import/Open uses pinned TraceDraw Rust crates statically compiled into a bundled Narwhal helper and isolated by the native process supervisor. This multiversion helper is not available in the Mac preview. These paths require no separately installed executable or service. Curves, source layers, per-object colours, ordinary plot widths, and exact 0.003-inch Hairline survive the supported path; output defaults to genuine v15 for CorelDRAW 2015/X7 compatibility, with v17 available as an explicit Export/Print option. Other generations and explicitly unsupported structures may use an optional local CLI fallback with a visible note; malformed files are refused without silently switching parsers.
