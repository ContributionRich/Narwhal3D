## Ownership and compatibility

`Editor` entries live in a process-local mutex-protected registry. Handles are
monotonic, nonzero, never recycled or pointers. Close is explicit and also performed
by a Python weakref finalizer. Copy/deepcopy clone the Rust entry under a new handle;
mutations cannot cross between fields. Stale/closed handles are rejected. Objects
are UI-thread-confined (as the previous model was); the registry serializes FFI
access but the Python facade does not promise concurrent compound operations.

Rust stores `Vec<u32>` so indices match Python code points rather than UTF-8 bytes.
Normalization, printable classification, limits, edits, selection transitions and
line movement use the qualified algorithms from pure_core, not its adapter. Raw
assignment preserves controls and lone surrogates; set_text/insert normalize them.
The Unicode 15.1 classifier is retained from the qualified port. Unicode 16.0 is
generated by `python3 native/ui_core/gen_unicode.py`; generation requires a Unicode
16 CPython. Other Unicode versions use a named complete legacy path, never a nearby
table. This host's entire Unicode 16 domain was differentially checked. A fresh
Unicode 15.1 interpreter run remains for Main/platform acceptance.

Python keeps an immutable text cache and a fixed native state projection, not a
second writable editing authority. Each mutation returns a revision and, when text
changes, the old `[change_start, change_end)` plus inserted count. A fresh cache
is updated from those Rust-authored bounds and a revision-checked native range read.
The host cannot decide an edit from that cache. If more than one edit occurred
without reading text, it reads the current full text instead of replaying edits.
Movement needs one scalar FFI call, zero text transfer, and no native allocation.
The native text revision does not change on movement/selection/configuration.

The public constructor, attributes and methods remain available. Raw text assignment
that would put the old caret/anchor outside its bounds, exotic attribute values,
subclasses and user-defined coercions use one-way atomic legacy handover **before**
executing the operation. First read all native state, then close, publish the legacy
state and execute exactly once. The retained implementation preserves error ordering
(including an anchor changed before failed int conversion). No second native owner
is created afterward. Huge method movement integers can safely saturate; huge
attribute limits retain their exact value via handover.

Python is required here for ctypes, GC integration, arbitrary Python object semantics
and the existing immutable-string caller API. Editing algorithms remain in Rust.
Clipboard, font measurement, drawing and event handling are outside this core.

## Loader / failures

- Development override: `NARWHAL_UI_CORE_LIBRARY=/absolute/path/to/library`.
- Default: beside `native_textfield.py`, under `native/`, with platform name
  `libnarwhal_ui_core.so`, `libnarwhal_ui_core.dylib` or `narwhal_ui_core.dll`.
- Missing *default* library: complete legacy behavior, `_backend_reason` names why.
- Missing/broken *configured* library, bad ABI or missing export: explicit error.
- Mutation/read failure or malformed projection: stop using that owner and raise;
  never return an empty replacement field, silently fall back or retry an edit.
- No library reload while handles live. The library object is kept by each owner
  and finalizer. A forged reply may leave an unreachable allocation in a broken
  library; do not trust its purported handle enough to close another field.

The internal `_native`, `_backend_reason` and traffic counters exist for focused
qualification, not as a new public TextField API.

## Typed C ABI

`narwhal_ui_core.h` is the authoritative declaration. ABI getter returns `1`.
All integers and u32 code points are native-endian. `State` is exactly **88 bytes**
on the qualified 64-bit targets. Input/output buffers must be valid, aligned and
exclusively accessible during a call; arbitrary invalid pointers cannot be checked.
The Python adapter makes an aligned ctypes u32 input allocation from encoded text.
Lengths/counts are code points, output_bytes is bytes. Buffers belong to the caller;
no Rust pointer or allocation is exported. Do not alias input/output buffers.

Every edit, create and clone supplies a full State buffer; anything other than the
exact size is rejected **before mutation**. There is no sizing retry for mutations.
Read is pure, checks the text revision and range, and copies exactly count code
points. Insufficient/wrong counts do not change the document. A consumer must check
status and bounds before allocation or reading. The adapter validates projections
before using their lengths/change ranges. Malformed replies are terminal, not replay.

State fields: handle; operation revision; text revision; length; caret; anchor
(`-1` means None); max_chars (meaningful only with flag 2); flags; change_start;
change_end; inserted. Flags: multiline=1, has_limit=2, boolean_result=4,
Unicode16=8 (otherwise Unicode15.1). Revisions start at 1, never wrap.

| Op | Meaning | value / input flags / payload |
|---|---|---|
| 0 | create | limit; multiline=1, has_limit=2, Unicode16=8; text |
| 1 | set_text | text |
| 2 | insert | text; boolean result |
| 3, 4 | backspace, delete | none |
| 5, 6 | set_caret, move | index/delta; select=1 |
| 7, 8 | home, end | select=1 |
| 9 | select_all | none |
| 10 | independent clone | returns new handle |
| 11 | raw text assignment | text; reject invalidated indices |
| 12 | raw caret assignment | in-range value |
| 13 | raw anchor assignment | in-range value; None=1 |
| 14 | multiline assignment | value 0 or 1 |
| 15 | limit assignment | value; None=1 |
| 16 | delete_selection | boolean result; clear even collapsed anchor |

Cut obtains immutable selected text before deleting the selection; no text output
buffer can fail after the cut has mutated. Empty cut retains the existing anchor.

Status: 0 success, 1 bad descriptor/argument, 2 stale/closed handle or read revision,
3 bound/range, 4 poisoned registry. Returned native errors do not mutate an entry.
OURS resource limits: 16,777,216 code points per text/input, 65,536 live handles,
u64 handle/revision exhaustion refused. Python hands over oversized text operations
before native entry, preserving the unbounded legacy contract. Genuine allocation
exhaustion can abort the process like other native allocators; these are not hostile
process isolation boundaries. No application callbacks run under the native mutex.

## Layout: explicit narrower scope

All four production Python layout helpers are unchanged. They retain exact
non-additive substring measurements, soft-wrap/caret ties, earlier hit-test ties,
newline highlight behavior, negative/zero-width behavior and NoProgress refusal.
`spike/test_ui_core_layout.py` compares results **and callback sequence/errors** with
an independent `168212d4` source reference, including stateful and failing callbacks.

Test-only `layout_algorithm.rs` reuses qualified algorithms. `layout_contract.rs`
prototypes an exact-substring metric cache with an explicit complete epoch (font
instance/revision, size, style, text and width). Each component invalidates it;
a provider failure is terminal for that epoch and never invokes the callback twice.
No sum of individual glyph widths substitutes for shaping. Cache memory is bounded.
These modules are cfg(test), absent from the shared library and public API.

**Unresolved production interface:** callers must supply a stable font instance,
font/shaping revision, size/style revision and a purity guarantee for measurements.
The current `measure(str)` function alone supplies none. Caching by function identity
or text revision would be unsound; calling BLF through repeated ctypes callbacks is
also not a qualified performance design. Main may supply an optional explicit metric
provider/epoch boundary later, or qualify a native shaping/font route. Do not alter
callers just to infer one. Editing does not depend on resolving this request.

## Build / focused qualification

From repository root, with at least 4 GiB available desktop RAM, one worker:

```sh
flock -w 60 /tmp/narwhal3d-heavy-build.lock cargo test --manifest-path native/ui_core/Cargo.toml --target-dir /tmp/narwhal-ui-core -j 1
flock -w 60 /tmp/narwhal3d-heavy-build.lock cargo build --release --manifest-path native/ui_core/Cargo.toml --target-dir /tmp/narwhal-ui-core -j 1
NARWHAL_UI_CORE_LIBRARY=/tmp/narwhal-ui-core/release/libnarwhal_ui_core.so python3 -B spike/test_ui_core_editor.py
NARWHAL_UI_CORE_LIBRARY=/tmp/narwhal-ui-core/release/libnarwhal_ui_core.so python3 -B spike/test_ui_core_callers.py
NARWHAL_UI_CORE_LIBRARY=/tmp/narwhal-ui-core/release/libnarwhal_ui_core.so python3 -B spike/test_ui_core_layout.py
NARWHAL_UI_CORE_LIBRARY=/tmp/narwhal-ui-core/release/libnarwhal_ui_core.so python3 -B spike/test_ui_core_mutations.py
NARWHAL_UI_CORE_LIBRARY=/tmp/narwhal-ui-core/release/libnarwhal_ui_core.so python3 -B spike/test_ui_core_benchmark.py
python3 -B spike/test_textfield.py
```

The mutation driver takes its own compiler lock; do not wrap the driver in that lock.
It mutates disposable external copies, records logs there, restores the copies and
runs controls. No shared source is transiently broken. Caller audits run unchanged
suites and count actual native constructions. Layer acceptance uses unchanged AST
function bodies with redraw stubbed, **not real Blender events**.
