# Required native vector/DXF encoding and Tween computation

These are source changes after the published 0.4.13 packages. Rebuild/stage matching natives; no existing release asset is relabeled or replaced.

## Replaced computation

- Rust owns PDF/AI/SVG serialization, numeric formatting, grouping, escaping, units, precision and output validation. Stroke and public writer APIs remain. AI stays a deliberate PDF alias. Independent original captures cover 750 exact byte cases, including RGB ties, signed zero, units and title semantics. Unused private Python emitters are retired, not reimplemented behind a fallback.
- Rust owns DXF serialization, layer merge/order, color handling and explicit unit/version headers. LINE/CIRCLE/ARC/POLYLINE/SPLINE entities keep their original analytic representation and valid bytes; no export tessellation is introduced. Public unit_header and INSUNITS remain available. Nonfinite fields, nonpositive radii and illegal line-breaking names refuse before file mutation.
- Rust owns compatible Tween control math, normalization/rehomogenization, knot matching, sample blending and sample-length target arithmetic. Python retains SDK getters, Curve.PointAt, existing arc-length orchestration and NURBS construction. Exact independent full-curve rational/open/closed captures preserve controls, weights, knots, domains and evaluations. Old tween_controls ABI remains unchanged.
- Obsolete OBJ/DXF/vector adapters, caches, selectors and counters are removed from native_pure.py; live decoders and the OBJ packer remain. Legacy C exports retain independent direct Rust compatibility coverage.

## Admission, files and safety

Startup now checks real bindings for all 26 required constructor/encoder exports before reporting readiness. A parser-working stale primary cannot be rescued by a different secondary library. Missing/stale/protocol errors raise actionable RuntimeError, without Python replay or partially published geometry.

Encoding and validation complete before opening a destination. Ordinary open/write/close behavior is retained, including symlinks, hard links, modes and actual OS errors. Native buffer publication/copy/free is transactional; this does not introduce atomic filesystem replacement or promise that arbitrary I/O failures preserve existing bytes.

Core ABI 1 and parser identity remain unchanged; auxiliary retirement probe 23 checks 22 exports. DXF owned ABI 2 requires the matching descriptor layout. Native metadata, UTF-8, capacity, ownership, failure atomicity and typed reasons are tested independently. Exact geometry, historical project files and the single Undo history are unchanged.

## Evidence and performance

Linux strict source gate passes 29 Rust integration suites and 77 host suites. Actual Windows MSVC passes 504 Rust tests and the final 22-export semantic probe, plus vector/DXF/Tween host tests; the Linux shell-launcher admission is not presented as Windows certification. Original expectations are captured independently, not generated by the tested Rust implementation.

Large DXF workloads improve; ordinary large PDF/SVG can be near parity with previous native production. Tiny exports pay tens of microseconds of boundary cost. Tiny compatible Tween measured about 19 microseconds slower; larger compatible construction about 8 percent faster, with SamplePoints near parity. No universal 10 percent win is claimed and no hidden Python fallback masks the tradeoffs.

Removed originals/hashes remain locally ignored. Public tests consume independent data, never a private backup or public Python reference engine. macOS remains unqualified and published release packages are unchanged.
